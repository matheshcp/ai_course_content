1. Fetch with retry / backoff (fixture fallback)

Nothing here needs an API key or a third-party package — urllib ships with Python. Three habits separate a demo fetch from a polite one: identify yourself with a User-Agent, treat 429 and 5xx as temporary (sleep, then retry) while other 4xx codes mean your request is wrong (stop), and fall back to the shipped offline_fixture.json so the lab still completes with no network.

import json, os, time, urllib.error, urllib.request

API_URL = (
    "https://api.open-meteo.com/v1/forecast"
    "?latitude=-37.81&longitude=144.96"
    "&daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max"
    "&timezone=auto&forecast_days=3"
)
FIXTURE = "offline_fixture.json"
CACHE = "api_cache.json"

def fetch_json(url, cache_path=CACHE, fixture=FIXTURE,
               timeout=10, max_retries=4, use_network=True):
    """GET JSON with exponential backoff. Falls back to local fixture."""
    if os.path.exists(cache_path) and use_network is not None:
        # Prefer fresh cache only if caller allows; default: try network first below
        pass
    if not use_network:
        with open(fixture, encoding="utf-8") as f:
            return json.load(f), "fixture"
    last_err = None
    for attempt in range(max_retries):
        try:
            req = urllib.request.Request(url, headers={"User-Agent": "ailab-lab08/1.0"})
            with urllib.request.urlopen(req, timeout=timeout) as resp:
                if resp.status == 429:
                    raise urllib.error.HTTPError(url, 429, "Too Many Requests", resp.headers, None)
                data = json.loads(resp.read().decode("utf-8"))
            with open(cache_path, "w", encoding="utf-8") as f:
                json.dump(data, f, indent=2)
            return data, "network"
        except urllib.error.HTTPError as e:
            last_err = e
            if e.code == 429 or e.code >= 500:
                time.sleep(2 ** attempt)  # 1s, 2s, 4s, 8s
                continue
            break  # 4xx other than 429: don't retry
        except (urllib.error.URLError, TimeoutError, OSError) as e:
            last_err = e
            time.sleep(2 ** attempt)
    print(f"network failed ({last_err}); using fixture")
    with open(fixture, encoding="utf-8") as f:
        return json.load(f), "fixture"

# Try network; if you're offline or Colab blocks egress, fixture kicks in.
payload, source = fetch_json(API_URL, use_network=True)
print("source:", source)  # network | fixture
print(list(payload.keys()))

What to notice:

  • source: reads network on a live run and fixture offline — both paths hand back the same key structure, so every later cell runs either way.
  • Backoff waits 1s, 2s, 4s, 8s (2**attempt over max_retries=4) instead of hammering the endpoint in a tight loop.
  • A successful fetch rewrites api_cache.json; the header User-Agent: ailab-lab08/1.0 identifies the client in the server’s logs.
Why backoff? Hammering a 429 endpoint gets your IP banned. 2**attempt spreads retries out (1s, 2s, 4s, 8s); always set a User-Agent so operators can trace and contact you instead of blocking the whole IP.
Pitfall: Rate limits are per client/IP, not per script. Retry only 429 and 5xx — a 404 or 401 will fail again forever, which is why the loop breaks on other 4xx. Add a little jitter to each sleep in real jobs, or every worker wakes in lockstep, fires together, and earns another 429.
Pitfall: Cache stampede — when api_cache.json goes stale, many readers can miss together and all fire the same GET (or all recompute), spiking the API into 429s. A one-user script can ignore this; a service should keep serving the stale cache while a single request refreshes it.

2. Inspect and flatten nested JSON

The API answers with a nested object: a daily block holding one array per metric, all arrays index-aligned. Analysts want rows, not parallel arrays. Walk the time array and, at index i, pull the i-th element from every metric — a zip by position — so each forecast day becomes one flat dict ready for a DataFrame.

print("timezone:", payload.get("timezone"))
daily = payload["daily"]          # nested object
times = daily["time"]             # parallel arrays
print("days:", times)

# Flatten: one dict per day
records = []
for i, day in enumerate(times):
    records.append({
        "date": day,
        "tmax": daily["temperature_2m_max"][i],
        "tmin": daily["temperature_2m_min"][i],
        "precip_prob": daily["precipitation_probability_max"][i],
        "source": source,
    })
print(records[0])
# e.g. {'date': '2026-09-22', 'tmax': 15.4, 'tmin': 8.2, 'precip_prob': 20, 'source': 'fixture'}

Mental model: API gave you column-oriented JSON; analysts want row-oriented records.

What to notice:

  • daily.time lists 3 dates — the forecast_days=3 query parameter at work, not a coincidence.
  • Every metric array shares that length; index i means the same calendar day in every array (the parallel-array contract).
  • The sample record carries keys date, tmax, tmin, precip_prob, source; live temperatures change run to run, so later asserts pin structure only.

3. DataFrame (or list) + save CSV

pandas turns the list of dicts into a table in one line. When pandas is missing, the stdlib csv.DictWriter writes the same file keyed off records[0].keys(). Either path produces api_snapshot.csv for Excel or a ticket attachment.

try:
    import pandas as pd
    df = pd.DataFrame(records)
    print(df)
    df.to_csv("api_snapshot.csv", index=False)
except ImportError:
    import csv
    with open("api_snapshot.csv", "w", newline="", encoding="utf-8") as f:
        w = csv.DictWriter(f, fieldnames=list(records[0].keys()))
        w.writeheader(); w.writerows(records)
    print("wrote api_snapshot.csv (stdlib)")

print("saved api_snapshot.csv rows:", len(records))  # 3

What to notice:

  • 3 data rows plus a header — Solution 3 counts exactly 4 lines including the header.
  • index=False keeps an unnamed index column out of the CSV; date already serves as the natural key.
  • The stdlib branch writes the same columns for a small record set — good enough for snapshots.

4. Cache behaviour

Caching is what lets the notebook re-run without another HTTP round trip: use_network=False skips urlopen entirely and reads locally. It doubles as a rehearsal for the offline path — same function, same return shape, only the source label changes.

# Second call with use_network=False reads the fixture (or your cache) — no HTTP.
payload2, src2 = fetch_json(API_URL, use_network=False)
print("second source:", src2)  # fixture
print("fixture keys:", sorted(payload2.keys()))
assert "daily" in payload2, "fixture must expose a daily block"

# If you saved a real network response, inspect the cache file:
if os.path.exists(CACHE):
    with open(CACHE, encoding="utf-8") as f:
        print("cache bytes:", len(f.read()))

What to notice:

  • second source: fixture — no packet left the machine, and the assert "daily" in payload2 still guards the structure the rest of the lab needs.
  • Sorted fixture keys reveal the top-level shape without dumping the whole payload.
  • When api_cache.json exists, its byte count is quick proof the earlier live fetch really landed on disk.
  • Every assert in this lab checks structure — keys, row counts, file existence — never live weather values, which legitimately differ between runs.

# --- Solution 1 ---
import time
def retry_demo(max_retries=4, sleep=time.sleep):
    sleeps = []
    for attempt in range(max_retries):
        # pretend attempt < 2 raises 429
        if attempt < 2:
            w = 2 ** attempt
            sleeps.append(w)
            sleep(w)
            continue
        return {"ok": True, "attempt": attempt}, sleeps
    return None, sleeps
# Use real time.sleep in production; in tests inject sleep=lambda s: None.
data, schedule = retry_demo(sleep=lambda s: None)
print("sleeps:", schedule, "-> success at", data["attempt"])
# sleeps: [1, 2] -> success at 2
