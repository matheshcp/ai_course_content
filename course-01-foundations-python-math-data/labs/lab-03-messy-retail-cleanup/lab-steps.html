Data Quality Track: From Dirty Warehouse Export to Clean CSV

Scenario: Warehouse hands you warehouse_messy_data.csv — 1000 rows of product inventory with mixed-case names, Quantity as "two hundred" / "NaN", missing prices, inconsistent Status. Clean it with a reproducible pipeline and report stock value by Category. You will learn: string normalisation, numeric coercion with fallbacks, date parsing (dd/mm/yyyy), validation rules, writing a cleaned CSV. Time: ~60 minutes. Level: Beginner–Intermediate. Needs: Python 3.8+ (pandas optional). Env: 🟢 Colab only.

Dirty-data mental map

Why it matters: warehouse and survey exports fail in predictable ways — messy casing, numbers written as words, sentinel strings like "NaN", unexpected category levels, ambiguous dates. 1. Load and profile (local first, Colab fallback)

Why it matters for analysts: profiling before cleaning is the step juniors skip and seniors refuse to. Value counts on Status and Quantity reveal the dirty levels (Low Stock, "two hundred", "NaN") before you write a single parse rule, so the cleaning code you write next is driven by evidence from the file rather than guesses.

import csv, os, math, re
from datetime import datetime
from collections import defaultdict, Counter

def load_rows():
    local = "warehouse_messy_data.csv"
    if not os.path.exists(local):
        import urllib.request
        urllib.request.urlretrieve(
            "https://raw.githubusercontent.com/eyowhite/Messy-dataset/main/warehouse_messy_data.csv",
            local,
        )
    with open(local, newline="", encoding="utf-8-sig") as f:
        return list(csv.DictReader(f))

rows = load_rows()
print(len(rows), "rows")
print("columns:", list(rows[0].keys()))
# 1000 rows
# columns: ['Product ID', 'Product Name', 'Category', 'Warehouse', 'Location',
#           'Quantity', 'Price', 'Supplier', 'Status', 'Last Restocked']

print("Status values:", Counter(r["Status"] for r in rows))
# {'In Stock': 340, 'Out of Stock': 332, 'Low Stock': 328}

print("Quantity samples:", Counter(r["Quantity"] for r in rows).most_common(6))
# includes 'two hundred': 160, 'NaN': 158
Profile first: value counts on categorical fields catch dirty levels (Low Stock) before you write cleaning code.

What to notice:

  • 1000 rows × 10 columns (Product ID … Last Restocked) — confirm the header list matches what warehouse promised; a renamed column breaks every later r["Quantity"] lookup with KeyError.
  • Status has exactly three observed levels: In Stock: 340, Out of Stock: 332, Low Stock: 328. The first two are business-valid; Low Stock is the surprise level Exercise 2 will force you to handle explicitly rather than ignore.
  • Quantity is not numeric: among the top raw values you already see 'two hundred': 160 and 'NaN': 158 — about a third of the file needs a custom parser, not a plain int().
  • encoding="utf-8-sig" strips a UTF-8 BOM if present; without it the first header can arrive as "ï»¿Product ID" (or similar mojibake) and every keyed access fails mysteriously.
Pitfall: Never start cleaning before this profile step. If you'd assumed Quantity was always digits, int(r["Quantity"]) would crash on row 1 of "two hundred" — and if you'd assumed Status was a closed set of two values, all 328 Low Stock rows would pass a naive filter silently. Value counts turn those surprises into known facts before code depends on them.

2. Clean text columns

Why it matters for analysts: free-text columns are where silent mismatches breed — " gadget y ", "GADGET Y", and "Gadget Y" are three different group-by keys until you normalise. One shared clean_text function applies the same strip/title rule to Product Name, Category, Warehouse, Location, and Supplier, so joins and aggregations compare like with like.

def clean_text(value):
    if value is None:
        return ""
    s = str(value).strip()
    if s.lower() in ("nan", "none", ""):
        return ""
    return s.title()  # ' gadget y ' -> 'Gadget Y', 'ELECTRONICS' -> 'Electronics'

for r in rows[:3]:
    print(repr(r["Product Name"]), "->", clean_text(r["Product Name"]),
          "|", r["Category"], "->", clean_text(r["Category"]))
# ' gadget y ' -> 'Gadget Y' | ELECTRONICS -> Electronics

What to notice:

  • The sample line shows ' gadget y ' → 'Gadget Y': surrounding spaces disappear via .strip(), and .title() fixes both the lowercase words and the residual casing in one call.
  • ELECTRONICS → Electronics: title-casing collapses ALL CAPS category labels into the display form you'll print in the final stock-value table, so Electronics and ELECTRONICS cannot split into two buckets.
  • Sentinel text ("nan", "none", blank) maps to '' before title-casing, preventing a literal "Nan" string from masquerading as a real product name.
  • Using repr(...) in the print keeps hidden spaces visible in the raw value — without repr, ' gadget y ' and 'Gadget Y' look identical in the terminal and you can't tell cleaning did anything.
Pitfall: .title() is aggressive on abbreviations and embedded capitals: "WiFi" becomes "Wifi" and "SKU-12a" becomes "Sku-12A". For this dataset's product/category names that's acceptable and matches the expected outputs; if you later clean IDs or brand codes, title-case only human-name columns, never key columns like Product ID.

3. Parse Quantity (word-numbers + missing)

Why it matters for analysts: inventory systems and form exports sometimes store counts as English words ("two hundred") or sentinel strings ("NaN"). A single parse_qty that returns int or None keeps "we don't know" distinct from "zero units" — a distinction that decides whether a row can contribute to stock value later.

WORDMAP = {
    "zero": 0, "one": 1, "two": 2, "three": 3, "four": 4, "five": 5,
    "six": 6, "seven": 7, "eight": 8, "nine": 9, "ten": 10,
    "twenty": 20, "thirty": 30, "forty": 40, "fifty": 50,
    "hundred": 100, "thousand": 1000,
}

def parse_qty(q):
    """Return int quantity or None. Handles '300', 'two hundred', 'NaN'."""
    q = str(q).strip().lower()
    if q in ("", "nan", "none"):
        return None
    try:
        return int(float(q))
    except ValueError:
        total = 0
        tokens = q.replace("-", " ").replace("and", " ").split()
        if "hundred" in tokens:
            i = tokens.index("hundred")
            total += (WORDMAP.get(tokens[i - 1], 1) if i > 0 else 1) * 100
            tokens = tokens[i + 1:]
        if "thousand" in tokens:
            i = tokens.index("thousand")
            total += (WORDMAP.get(tokens[i - 1], 1) if i > 0 else 1) * 1000
            tokens = tokens[i + 1:]
        for t in tokens:
            total += WORDMAP.get(t, 0)
        return total if total else None

print(parse_qty("300"), parse_qty("two hundred"), parse_qty("NaN"))
# 300 200 None

qty_ok = sum(1 for r in rows if parse_qty(r["Quantity"]) is not None)
print("qty parseable:", qty_ok)  # 842 of 1000 (158 are NaN)

What to notice:

  • The three-way demo prints 300 200 None: plain digits go through int(float(...)) (also accepting "300.0"), "two hundred" hits the word branch and becomes 200, and "NaN" returns None rather than raising — missing stays missing.
  • 842 of 1000 quantities parse, which is 1000 − 158 exactly matching the profiled 'NaN': 158 count — your parser's coverage reconciles against the earlier Counter instead of being a mystery number.
  • The WORDMAP covers zero–ten, tens up to fifty, plus hundred/thousand; hyphens and the word and are normalised away ("twenty-five" / "twenty and five" both tokenize cleanly).
  • total if total else None means an unrecognised-only word string that sums to 0 is treated as unusable (None), not as a confident zero — conservative for inventory math.
Pitfall: int("two hundred") raises ValueError, and float("NaN") succeeds but produces a special float that is not equal to itself — so a bare try/except around float() is not enough: you must reject ""/"nan"/"none" up front (as this function does) and never let a NaN float flow into Stock Value. Always decide in the parser whether a value is absent (None) before any arithmetic sees it.

4. Parse Price (reject NaN) and dates

Why it matters for analysts: prices and restock dates look numeric/dated until one "NaN" or 20/12/2022 row poisons a SUM or a sort. parse_price strips currency noise and rejects missing sentinels; parse_date tries explicit formats in order so dd/mm/yyyy warehouse dates become real date objects you can filter and range-check.

def parse_price(p):
    """Float price or None. Rejects NaN/empty."""
    s = str(p).strip().replace("$", "").replace(",", "")
    if s.lower() in ("", "nan", "none"):
        return None
    try:
        v = float(s)
        return None if math.isnan(v) else v
    except ValueError:
        return None

def parse_date(s):
    """dd/mm/yyyy or ISO; None if missing."""
    s = str(s).strip()
    if s.lower() in ("nan", "none", ""):
        return None
    for fmt in ("%d/%m/%Y", "%Y-%m-%d", "%m/%d/%Y"):
        try:
            return datetime.strptime(s, fmt).date()
        except ValueError:
            continue
    return None

print(parse_price("19.99"), parse_price("NaN"))   # 19.99 None
print(parse_date("20/12/2022"), parse_date("NaN"))  # 2022-12-20 None

price_ok = sum(1 for r in rows if parse_price(r["Price"]) is not None)
date_ok  = sum(1 for r in rows if parse_date(r["Last Restocked"]) is not None)
print("price ok:", price_ok, "date ok:", date_ok)  # 793 price, 800 date

What to notice:

  • parse_price("19.99") → 19.99 but parse_price("NaN") → None: the string "NaN" is caught by the sentinel check, and a float that somehow becomes a real math.nan is caught by math.isnan — two layers for the same class of bug.
  • parse_date("20/12/2022") → 2022-12-20 (day 20, month 12): %d/%m/%Y is tried first, so unambiguous European dates land correctly; "NaN" → None matches the price parser's missing-value convention.
  • Coverage differs by column: 793 prices and 800 dates parse out of 1000 — roughly 207 and 200 rows are unusable for value/timeline questions, numbers you should quote alongside any total rather than hiding.
  • Round-tripping through str(p).strip().replace("$", "").replace(",", "") means "$1,234.50" and "1234.50" both parse to the same float, which matters for mixed export styles.
Pitfall: float("NaN") does not raise — it returns a NaN float, so try/except ValueError alone would let NaN into your sums (and NaN poisons every total it touches). The explicit math.isnan(v) / "nan" sentinel checks are mandatory. Separately, date format order is a silent trap: "%m/%d/%Y" before "%d/%m/%Y" would misread 05/04/2022 as May 4 instead of 5 April; this loader tries day-first first to match the warehouse's documented dd/mm/yyyy export.

5. Validate Status and build cleaned rows

Why it matters for analysts: validation is not the same as deletion. By attaching a boolean Status OK flag (and a derived Stock Value) while keeping every row, you give auditors a column they can filter on — proving what was excluded and why — instead of a smaller file where bad rows have vanished without a trace.

ALLOWED_STATUS = {"In Stock", "Out of Stock"}

def clean_row(r):
    qty = parse_qty(r["Quantity"])
    price = parse_price(r["Price"])
    status_raw = str(r["Status"]).strip()
    return {
        "Product ID": str(r["Product ID"]).strip(),
        "Product Name": clean_text(r["Product Name"]),
        "Category": clean_text(r["Category"]),
        "Warehouse": clean_text(r["Warehouse"]),
        "Location": clean_text(r["Location"]),
        "Quantity": qty,
        "Price": price,
        "Supplier": clean_text(r["Supplier"]),
        "Status": status_raw,
        "Status OK": status_raw in ALLOWED_STATUS,
        "Last Restocked": parse_date(r["Last Restocked"]),
        "Stock Value": round(qty * price, 2) if (qty and price) else None,
    }

cleaned = [clean_row(r) for r in rows]
bad_status = [c for c in cleaned if not c["Status OK"]]
print("invalid status rows:", len(bad_status), "->", Counter(c["Status"] for c in bad_status))
# 328 -> {'Low Stock': 328}
print("sample cleaned:", cleaned[0])
Status OK is a flag column, not a silent drop — auditors need to see what you excluded.

What to notice:

  • 328 invalid-status rows, all with Counter({'Low Stock': 328}) — the entire invalid bucket is the one unexpected level from the Section 1 profile, so len(bad_status) matches Status count math: 340 + 332 + 328 = 1000.
  • ALLOWED_STATUS is a set, so status_raw in ALLOWED_STATUS is O(1) and immune to trailing-space misses because status_raw is stripped first — "In Stock" passes, " Low Stock " would still be caught after strip.
  • Stock Value is computed only when qty and price are both truthy; any row with missing qty, missing price, or a 0 value gets None instead of a fake 0.00, so downstream sums can't pretend missing inventory was valued at zero.
  • cleaned still has len(cleaned) == 1000 — cleaning transformed fields and added flags; it did not drop rows, which is what makes the later category totals auditable against the original file.
Pitfall: if (qty and price) treats quantity 0 (and price 0.0) as unusable and sets Stock Value to None. That's usually right for "value of sellable stock," but it conflates zero units with missing units. If you need to distinguish them, change the guard to if qty is not None and price is not None and let a genuine zero contribute 0.0 — just be aware the expected grand total (2949939.00 over 661 usable rows) is computed under the truthy-guard convention shown here.

6. Stock value by Category + write clean CSV

Why it matters for analysts: this is the deliverable the whole pipeline exists for — a category-level stock-value report plus a reusable clean file. Aggregating only rows where both quantity and price parsed (rather than coercing blanks to zero) keeps the total honest, and writing warehouse_clean.csv means the next report starts from validated data instead of redoing the cleanup.

by_cat = defaultdict(lambda: {"rows": 0, "value": 0.0, "units": 0})
for c in cleaned:
    cat = c["Category"] or "Unknown"
    by_cat[cat]["rows"] += 1
    if c["Stock Value"]:
        by_cat[cat]["value"] += c["Stock Value"]
        by_cat[cat]["units"] += c["Quantity"] or 0

for cat in sorted(by_cat):
    b = by_cat[cat]
    print(f"{cat:12s}  rows={b['rows']:4d}  units={b['units']:6d}  value=${b['value']:,.2f}")
# Electronics  rows= 248  ... value=$830,214.00
# Clothing     rows= 257  ... value=$716,252.50
# Furniture    rows= 265  ... value=$796,211.50
# Toys         rows= 230  ... value=$607,261.00
print("TOTAL value:", round(sum(b["value"] for b in by_cat.values()), 2))
# TOTAL value: 2949939.0  (only rows with both qty and price: 661)

# Persist clean file next to the notebook
out_path = "warehouse_clean.csv"
fields = ["Product ID", "Product Name", "Category", "Warehouse", "Location",
          "Quantity", "Price", "Supplier", "Status", "Status OK",
          "Last Restocked", "Stock Value"]
with open(out_path, "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=fields, extrasaction="ignore")
    w.writeheader()
    for c in cleaned:
        row = dict(c)
        row["Last Restocked"] = str(c["Last Restocked"] or "")
        w.writerow(row)
print("wrote", out_path, "rows:", len(cleaned))

What to notice:

  • Four categories print with row counts 248 + 257 + 265 + 230 = 1000 — every profiled row lands in exactly one bucket (cleaned Category is never blank on this file, or "Unknown" would appear as a fifth line).
  • Values follow the comments: Electronics $830,214.00, Clothing $716,252.50, Furniture $796,211.50, Toys $607,261.00, summing to TOTAL value: 2949939.0 — and the annotation reminds you only 661 rows had both qty and price, not all 1000.
  • Row counts are inclusive (rows increments for every cleaned row) while value/units only accumulate when Stock Value is truthy — so you can see per category how much of its inventory was unpriceable without the total quietly absorbing zeros.
  • The writer uses extrasaction="ignore" so unexpected keys can't crash DictWriter, stringifies Last Restocked (date objects are not CSV-friendly; missing dates become ''), and still emits all 1000 rows with the Status OK flag preserved for auditors.
Pitfall: Never add a row to value when Stock Value is None by substituting 0 "just to keep the loop simple" — that wouldn't change the sum, but it would corrupt rows/units consistency and hide how much value is missing. Conversely, don't coerce missing price to 0 before multiplying: qty * None raises, and treating missing as $0 unit price understates inventory. Keep missing as None until the aggregation explicitly skips it (as if c["Stock Value"]: does).
